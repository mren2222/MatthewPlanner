# AI planner

Main calls `createPlannerReply(message, context, { apiKey, model })`. The AI module has no database dependency and returns proposals only. Under the approved 0.2.0 behavior, main validates clear commands and applies their proposals through ActionService immediately, retaining revision checks, audit and undo. Discussion and clarification suppress all mutations. Legacy pending proposals remain manually applicable. `reviewToday(context)` is a deterministic, read-only check-in; it no longer appears automatically at startup.

Without a key the clearly labelled offline helper recognizes a limited set of Chinese/English commands: task completion, named multi-task completion, explicit moves, Amazon preparation by day and duration, actual duration, and missed-task clarification. It is not a full AI model. Ambiguous matches ask for a specific task; unsupported commands ask for clarification. Stated work duration records activity without assuming completion. The provider does not invent measured durations. The completion service separately uses supplied duration, estimate or default for user-approved retrospective placement, retaining internal inferred source/confidence. The UI shows ordinary time ranges; see REDESIGN.md.

The live provider uses the OpenAI Responses endpoint with `text.format` strict JSON schema and `store:false`. The model is supplied from Settings. Main defaults to `gpt-5.6-luna` and upgrades the old saved `gpt-4o-mini` default without rewriting the credential file during startup. The next explicit settings save records a preference version, so a later explicit choice of 4o-mini is respected. Custom models and environment overrides remain configurable. Luna requests use `reasoning.effort: low`; other models do not receive that model-specific parameter. Requests have an 8,000-token output budget and 60-second timeout, including response-body reads.

Adjacent output text blocks are concatenated before JSON parsing, ignoring reasoning items. Strict wire-schema nullable optional fields are stripped, then the shared core action validator and context ID checks reject malformed proposals. Authentication, model access, credits/rate limits, rejected configuration, service unavailability, timeout, connection failure, unreadable JSON, output limits and invalid planning proposals have separate safe messages. Every failure returns no actions. Raw response bodies and exception messages are neither logged nor echoed, and there is no automatic retry that could incur another API charge. The optional `fetch` injection is for main-process tests. The earlier generic failure alone did not establish its precise cause; switching model or increasing the timeout is not proof of successful live access.

Only a bounded projection is sent: up to 80 relevant tasks, 30 upcoming fixed events, 30 activity records, 30 minimal audit entries, and up to 40 recent messages within 48,000 characters. User message context supports up to 16,000 characters so pasted Notes and clarification facts survive. Text fields and user input have length limits and redact recognizable credentials. Audit before/after snapshots and calendar credentials are excluded. Treat task text and chat history as untrusted input. Using a configured live provider sends the selected planning data and request to OpenAI; offline mode remains local. create_completed_task handles clearly identified completed work that has no existing task, without asking the user for internal IDs.

Completing a task now automatically creates a local retrospective block in the validated store. Supplied timing is preserved; missing intervals use the action time and supplied duration/estimate/default with internal inferred metadata. The user approved this placement convention and requested plain time labels in UI. Repeat completion is idempotent, reopening removes completion-generated activity, and undo restores both. Direct model-proposed inferred intervals still require safe ordering and no conflicts. Activity never becomes a fixed calendar event. Selected-email extraction has a separate restricted action policy and cannot complete tasks or record activity.

References: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna).
